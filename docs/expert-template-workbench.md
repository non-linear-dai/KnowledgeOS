# 专家工艺模板工作台

/templates 是独立于本体白板的标准工艺路线实例工作台。本体白板维护概念、谓词、规则和模型的定义；工作台只使用已发布的定义来创建专家确认的模板。两处使用不同的服务端权限，单靠切换页面不会获得写入权。

## 通用模板结构

- route_template 是不可原位覆盖的标准路线版本，声明制造类别、产出基准、专家作者和回归案例。
- route_group 是不计成本的重复、条件与汇合容器。重复组的 iteration_set 指向测算场景中的一个命名对象集合，例如内层线路面、机加工面、模具型腔或装配组件；对象之间可独立执行或依序执行。条件组在满足条件时执行一次组内流程。
- route_step 是一条路线中的工序出现位置，引用一个固定版本的 operation_template。cost_basis 声明工序对应的计费对象（板、面、件等语义标签）；实际资源数量倍率由 resource_plan 的 basis 和加工批量配置决定。
- operation_template 是可复用的标准工序，可声明方法、资源需求槽位和固定版本的确定性时间模型引用。时间模型的输出单位必须属于时长维度；材料、设备等实际单价仍由测算场景或连接器提供。
- decision_table 是独立、固定版本的规则表。路线工序或组通过 decision_binding 引用输出；布尔／等值输出控制是否加工，单一字符串输出选择固定版本的标准工序。
- 同级对象用 route_precedes 形成无环依赖图；组内工序用 group_contains 归属。重复组要求全部适用对象的组内工序完成后，后续节点才能开始。

新增谓词均在 control/predicates/ 注册。专家编写的标准模板作为规范性知识节点存于 knowledge/templates/、knowledge/operations/ 和 knowledge/decisions/；企业 PLM/MES 的实际生产路线仍通过连接器摄入，不复制为 Git Markdown。确定性公式定义存于 control/models/，工作台只选择模型版本和配置输入映射。

## 工作台流程

1. 以 template_author 身份登录，选择现有版本“复制为新版本”或新建模板。
2. 主区域是可编辑的工艺白板，重复组直接显示组内工序。点击节点名称就地改名；节点旁的加号插入下一道工序并衔接原有后续关系。标准工序库、案例、审核和模板设置通过左侧图标按需展开；卡片属性独立在右侧随选择显示。
3. 点击或拖入标准工序，拖动连接点维护前置关系；移入工序组可通过拖动或属性面板中的快捷按钮完成。批量粘贴每行一个工序名称可一次生成多工序链；匹配工序库名称时复用固定版本的工序，其余名称生成本次新增的标准工序。连线立即拒绝循环和跨层级连接；跳过可选工序或整组时，引擎自动衔接前后依赖。
4. 添加至少一个专家案例，录入场景事实、对象集合和预期展开工序数。点击“运行当前案例”检查展开结果，实际逻辑工序次数同步标注在白板节点上。
5. 提交为高风险 ChangeSet。template_reviewer 查看提案并再次试展开，由独立人员审核；template_publisher 将整套文件应用到 Git 真源，再验证发布。应用操作不会创建 Git commit。

规范版本发布后不可修改；维护时复制并递增版本。提案在写真源前可因控制定义、引用或样例变化而失效，需重新生成受审版本。所有模板写入都通过 ChangeSet，重复提交支持幂等键。
已应用到真源但尚未验证发布的模板包不进入公开模板目录，也不能通过模板读取 API 获取；编译器仍会检查其源文件。由人员直接以 Git 维护且没有关联 ChangeSet 的模板，按现有 Git 真源约定进入目录。

## 白板快捷操作

- N：在所选节点后追加工序；G：新增重复组。
- Command/Ctrl + D：复制所选工序或整组；组内工序和内部关系一并复制，组外依赖不自动复制。
- Command/Ctrl + Z、Shift + Command/Ctrl + Z：撤销与重做工序编辑、关系和节点拖动。
- Shift 框选或多选后可一次串联、复制或删除；Delete 删除所选工序或关系。
- 在白板粘贴文本打开批量工序清单；Command/Ctrl + Enter 确认生成。
- 拖动右侧连接点到下一工序的左侧连接点建立前置关系；选中连线后按 Delete 删除，或双击连线删除。

节点位置属于当前会话的编辑布局，正式模板持久化的是工序、组和前置关系。重新打开模板时按依赖自动布局；尚未提交的草稿仍保存在页面内存中。

## API 与权限

| API | 权限 | 用途 |
| --- | --- | --- |
| GET /v1/templates、GET /v1/templates/get?id=... | read | 浏览已发布模板和标准工序 |
| POST /v1/templates/preview | template_edit、template_review 或 template_publish | 只读、确定性展开样例 |
| POST /v1/templates/calculate | template_edit、template_review 或 template_publish | 只读、确定性资源成本试算 |
| POST /v1/templates/propose | template_edit | 校验整套模板与案例并创建高风险 ChangeSet |
| POST /v1/changesets/review，模板目标 | template_review | 独立审核 |
| POST /v1/changesets/apply、publish，模板目标 | template_publish | 应用真源、编译与登记 |

常规 agent、reviewer 和 publisher 权限不能操作模板目标；模板角色也不能借通用 propose 修改本体控制定义。即使经通用提案端点访问模板目录，也必须使用受验证的 template_package 格式。服务端基于目标路径执行这些限制。

## 示例：同一编排机制适用不同领域

PCB 模板将 iteration_set 配为 inner_surfaces，案例输入两个或六个内层线路面；组内蚀刻分别展开，压合作为组外工序只出现一次。机加工模板可将同一字段配为 surfaces，对每个加工面展开精铣，再汇合到整件检验。两者由同一验证器与展开器处理。

## DMN 式决策表

左侧“决策”维护表名称、稳定标识、版本、输入／输出列、规则行和默认输出。数值保留十进制字符串，避免编辑时丢失精度；单元格失焦或 Enter 提交，支持撤销。

- 输入来自场景 facts 或重复对象 item；列类型为 number、string、boolean，数值可声明注册单位。
- 条件支持等于、不等于、大小比较、闭区间、集合和任意值。每行各条件同时满足才命中。
- UNIQUE 在校验阶段拒绝重叠规则；FIRST 按行顺序取首个结果；COLLECT 返回所有命中结果。未命中时使用显式默认输出，没有默认的 UNIQUE／FIRST 会报错。
- 在工序／组属性面板选择表及输出。选择标准工序仅接受 UNIQUE／FIRST 的字符串输出，且所有候选工序必须存在。案例面板显示命中行、默认命中和输出；白板同步显示实际选择的工序与被跳过节点。

规则表保存于 `knowledge/decisions/<id>/v<version>.md` 的 `decision_definition` 属性；路线根节点的 `decision_assets` 记录本包新建表。表、标准工序和路线作为一个 ChangeSet 审核、应用和验证发布；待发布资产不能被其他草稿引用，已发布资产维护时复制为新版本。

这是 DMN 式的受限规则语义，尚未实现 DMN XML 导入导出和通用 FEEL。

## BPMN 式工艺白板

白板支持同级工序的顺序、并行依赖、条件组、单层逐对象重复、对象间独立／顺序执行，以及全部完成后汇合。简单条件可组合为 all／any，最多四层。条件和决策同时配置时，两者均满足才执行；缺少输入会报告错误，不自动猜测条件。

编排输出为有限、无环的逻辑工序实例及 precedence 图；实例和成本明细按前置关系排列。它表达工艺依赖；对象独立表示没有对象间依赖，不代表设备能够同时开工。当前没有 BPMN XML、事件、消息、补偿、无限循环或有限设备产能排程。

## 确定性计算模型

标准工序配置加工时间、准备时间、单次加工数量、模型输入映射和资源数量。计算场景另外维护产量、币种、资源单价、利润率与运营费率，场景试算参数不写入规范性模板。

1. 根据当前案例展开路线，并应用决策选择标准工序。
2. 每个逻辑工序加工次数 = ceil(产量 / 单次加工数量)。准备时间计一次，总时长 = 准备时间 + 单次加工时间 × 加工次数。
3. 资源 basis 可为 cycle（每次加工）、piece（每件产出）、time（随总时长）或 batch（整批一次）。按时长资源的 amount 表示资源数量，例如两名操作工配置 amount=2、unit=hour、basis=time。
4. 资源数量也可引用固定版本的 quantity_model_ref。输入来自 facts、item 或 process（duration_seconds、cycle_seconds、cycles、production_quantity）；输出换算为资源单位后再应用 basis。若能源模型已使用总时长，应配置 batch，避免再次乘加工次数或时长。
5. 资源数量换算为单价计量单位后乘单价。材料和零部件汇总为材料成本，设备、场地、能源、人工汇总为制造成本。Decimal 运算保留中间精度，最终按币种精度舍入；模型自身精度由已发布模型定义控制。
6. 合理单价 = 单位成本 / (1 − 利润率 − 运营费率)，这里两项比率均以销售收入为分母。

单价可使用本次试算值，或引用 KnowledgeOS 实例的已确认连接器观测（node_id、predicate、as_of）。观测须声明币种和 per_unit，或使用 CNY_per_hour 等明确计价单位；读取时检查生效时间、冲突与新鲜度，明细保留 assertion_id、source_refs、evidence_refs 和 source_hash。实际价格仍遵循原有连接器与断言审核流程。

缺少资源、价格、加工时长或模型输入时，返回已知小计和缺项列表，总成本、单位成本和合理价格为空。币种混用、单位不兼容、失效模型和非法比率直接拒绝。测算为只读预览，不创建正式计算运行记录或业务断言。尚未计算良率损耗、返工、税费、跨币种兑换或设备产能约束。

## 可操作的联动示例

登录后选择“模板 → 体验决策与成本示例”。示例仅创建页面草稿与虚构试算参数：低精度选择粗铣并跳过精整，高精度选择精铣并执行精整；两种案例分别展开 4／6 个工序。

左侧“案例”切换 standard／precision，“成本”运行试算。默认产量为 20，材料、设备、人工、场地和能源全部列入：standard 总成本 427.40、单位成本 21.37、合理单价 26.71 CNY；precision 总成本 734.80、单位成本 36.74、合理单价 45.93 CNY。可修改决策条件、加工批量和价格观察联动结果。

## 聚焦工艺的维护交互

属性编辑独立在右侧；单击任意工序或阶段卡片（包括名称）自动显示属性，点击白板空白、取消选择、删除所选卡片或按 Esc 后自动隐藏。只读模板也可选中查看属性。左侧工序库、案例、决策和审核工具保持独立，连续选择标准工序时无需来回切换到属性面板。较窄窗口一次展示一个侧栏：打开左侧工具时暂收属性，选中卡片或完成选型后切回属性；桌面宽窗口两侧可同时操作。条件、决策、阶段归属和前置关系按需展开，常用名称与标准工序保持直接可见。

新模板从空白画布起步。添加下一工序可点击卡片旁的加号或按 N；也可从工序库拖入。新增“工艺阶段”整组执行一次，可进一步配置启用条件；重复组按对象集合展开。阶段可折叠，目录也随之折叠，搜索仍可找到隐藏的子工序，点击结果会展开所属阶段并定位。折叠仅属于视图，不影响案例、工序数量与成本。

### 按阶段粘贴专家清单

左侧“批量添加工序”或白板粘贴入口接受普通名称清单、箭头分隔清单，以及包含阶段的文本。解析结果先展示阶段、对象集合、顺序与数量，点击“生成阶段和工序”或 Cmd/Ctrl+Enter 一次创建，并保留插入位置原有的后续依赖：

```text
[前处理]
清洗
涂膜
[内层线路 | 重复 | inner_surfaces]
曝光
显影
蚀刻
[整板加工]
压合
钻孔
检验
```

- `[名称]` 创建执行一次的阶段，映射为无条件的 `group_mode=conditional`，沿用现有工序组语义。
- `[名称 | 重复 | inner_surfaces]` 按集合对象独立展开；增加第四项 `顺序` 时，对象间顺序执行。
- `[主路线]` 回到主层级。不带阶段标题的清单可直接追加到现有阶段内部；不支持嵌套阶段。
- 每行可从表格粘贴两列：工序名称、固定版本的 `operation:标识:版本`。同名多个标准版本需指定引用；唯一匹配则复用，新名称创建待配置的标准工序草稿。
- 新的重复集合在案例里初始化一个对象，已有集合保持原内容。专家仍须维护真实案例对象数量、预期工序数、标准工序参数和资源；自动生成的结构与示例不能视为已确认生产路线。
- 一次生成超过 12 道工序时自动折叠新增阶段。每份模板上限 200 道工序和 200 个一层工序组，展开上限仍为 2,000 个逻辑实例。较长的芯片路线可按阶段编写；深层嵌套、跨模板子路线和完整设备排程尚未实现。

### 减少重复编辑

选择阶段后可一次选中组内所有工序，也可 Shift／Cmd／Ctrl 多选。批量属性仅应用专家勾选的计费对象、条件和决策字段；未勾选字段保持原值。明确勾选且未配置的条件或决策会被清除，界面给出提示。也可统一选择固定版本的标准工序，统一其引用和默认计费对象。使用对象条件的批量修改只允许重复组内工序，跨范围失败时整批不修改。

“复制并接在后面”（Cmd/Ctrl+Shift+D）保留阶段内部图，并将原后续依赖衔接到副本；普通复制（Cmd/Ctrl+D）仍创建独立副本。批量生成、复制和应用属性均支持一次撤销。Cmd/Ctrl+K 打开目录并聚焦搜索；属性顶部的上一／下一按钮或 Alt+↑／↓ 按前置关系导航。标准工序参数和资源可从卡片属性直接打开配置。

所有生成与批量编辑先停留在页面草稿中。提交仍通过整套模板与专家案例校验、高风险 ChangeSet、独立审核、应用真源和验证发布；本次交互不新增谓词，也不改变治理和确定性计算语义。

### 画布尺寸更新

节点测量通过当前工艺白板独立的 React Flow Provider 排队：同一帧合并节点测量通知，每个标识保留最新节点元素，下一帧再调用原始测量动作计算尺寸、连接点和父子位置。该队列在 React Flow 的节点观察器创建前安装，以覆盖内部状态更新；仅延迟外部 onNodesChange 无法覆盖内部同步布局。队列在卸载时取消，热更新重连时保留稳定的转发函数。此处理限于工艺白板，原生窗口错误仍正常报告。

卡片的追加、复制、属性和组内追加操作阻止点击冒泡，追加完成后保持新工序被选中，避免原卡片随后重新覆盖选择。尺寸、路由语义和成本模型仍由现有布局与确定性引擎维护。
